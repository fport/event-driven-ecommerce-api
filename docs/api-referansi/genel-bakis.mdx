# API Genel Bakis

Bu dokuman, Event-Driven E-Commerce platformunun RESTful API'sini tanimlar. Tum istekler API Gateway (API Gecidi) uzerinden yonlendirilir ve merkezi kimlik dogrulama ile hiz sinirlamasi uygulanir.

## Base URL (Temel Adres)

```
http://localhost:3000
```

API Gateway, tum mikroservislere tek bir giris noktasi saglar. Istemciler dogrudan arka plan servislerine degil, yalnizca gateway uzerinden erisim saglar.

## Kimlik Dogrulama Gereksinimleri

Tum `/api/*` yollari kimlik dogrulama gerektirir, **tek istisna** `/api/auth/**` yollaridir.

| Yol Deseni | Kimlik Dogrulama |
| --- | --- |
| `/api/auth/**` | Gerekli degil (herkese acik) |
| `/api/orders/**` | Session cookie (oturum cerezi) gerekli |
| `/api/products/**` | Session cookie gerekli |
| `/api/notifications/**` | Session cookie gerekli |
| `/api/search/**` | Session cookie gerekli |
| `/health` | Gerekli degil |
| `/metrics` | Gerekli degil |

<Note>
  Kimlik dogrulama, Better Auth kutuphanesi tarafindan yonetilir. Basarili giris sonrasinda tarayiciya bir session cookie (oturum cerezi) atanir. Sonraki tum isteklerde bu cerez otomatik olarak gonderilir.
</Note>

Kimlik dogrulama basarisiz oldugunda asagidaki yanit doner:

```json
{
  "success": false,
  "error": "Unauthorized"
}
```

## Rate Limiting (Hiz Sinirlamasi)

API Gateway, IP adresine dayali hiz sinirlamasi uygular. Redis tabanli sliding window (kayan pencere) algoritmasi kullanilir.

| Parametre | Deger |
| --- | --- |
| Maksimum istek | **200 istek / dakika** |
| Pencere suresi | 60 saniye |
| Kapsam | IP adresi basina |

Her API yaniti asagidaki rate limit header'larini (basliklarini) icerir:

```
X-RateLimit-Limit: 200
X-RateLimit-Remaining: 195
X-RateLimit-Reset: 45
```

| Header | Aciklama |
| --- | --- |
| `X-RateLimit-Limit` | Pencere basina izin verilen maksimum istek sayisi |
| `X-RateLimit-Remaining` | Kalan istek sayisi |
| `X-RateLimit-Reset` | Pencerenin sifirlanmasina kalan sure (saniye cinsinden) |

<Warning>
  Rate limit asimindan sonra tum istekler `429 Too Many Requests` durum kodu ile reddedilir. Pencere suresi dolana kadar beklemeniz gerekmektedir.
</Warning>

Rate limit asildigi zaman donen yanit:

```json
{
  "success": false,
  "error": "Too many requests"
}
```

## HTTP Hata Kodlari

| Durum Kodu | Anlami | Aciklama |
| --- | --- | --- |
| `400` | Bad Request | Gecersiz istek govdesi veya parametreler. Zod dogrulama hatalari bu kodla doner. |
| `401` | Unauthorized | Oturum cerezi eksik veya gecersiz. Giris yapmaniz gerekmektedir. |
| `404` | Not Found | Istenen kaynak (siparis, urun vb.) bulunamadi. |
| `422` | Unprocessable Entity | Is mantigi hatasi. Ornegin: saga checkout sirasinda yetersiz stok veya odeme basarisizligi. |
| `429` | Too Many Requests | Rate limit asildi. `X-RateLimit-Reset` basligindaki sureyi bekleyin. |

## Servis Yonlendirme Tablosu

API Gateway, gelen istekleri ilgili mikroservise yonlendirir:

| Gateway Yolu | Hedef Servis | Dahili Port |
| --- | --- | --- |
| `/api/auth/**` | Better Auth (gateway icinde) | 3000 |
| `/api/orders/**` | Order Service (Siparis Servisi) | 3001 |
| `/api/notifications/**` | Notification Service (Bildirim Servisi) | 3002 |
| `/api/products/**` | Inventory Service (Envanter Servisi) | 3003 |
| `/api/search/**` | Search Service (Arama Servisi) | 3004 |

<Tip>
  Gelistirme ortaminda servisleri dogrudan dahili portlarindan da test edebilirsiniz. Ornegin, Order Service'e dogrudan `http://localhost:3001/orders` adresinden erisebilirsiniz. Ancak bu durumda kimlik dogrulama atlanmis olur.
</Tip>

## Saglik Kontrolu

Her servis bir `/health` endpoint'i sunar. Gateway uzerinden saglik kontrolu yapmak icin:

```bash
curl http://localhost:3000/health
```

```json
{
  "status": "ok",
  "service": "api-gateway",
  "timestamp": "2026-03-03T10:30:00.000Z",
  "uptime": 3600.5
}
```
